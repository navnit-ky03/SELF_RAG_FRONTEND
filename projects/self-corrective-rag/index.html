02 / THE PROBLEM

What needed solving?

A retrieved document is not automatically a useful source. A fluent answer can still miss the question or go beyond the evidence.

THE APPROACH

A practical way through.

Route the question, retrieve context when needed, evaluate the evidence, and run a bounded correction path before returning a response or fallback.

03 / WHAT IT DOES

The useful pieces.

  • ↗Conditional retrieval and intent routing
  • ↗Relevant, grounded, and useful answer checks
  • ↗Bounded correction and conversational thread state
  • ↗Rate-limited, non-streaming FastAPI integration

04 / ENGINEERING DECISIONS

The work behind the workflow.

DECISION 01

Avoiding unconditional retrieval

Conditional routes use retrieval when the question needs project evidence.

DECISION 02

Containing correction loops

Bounded correction prevents unending retries when evidence is insufficient.

DECISION 03

Separating service and model health

GET / reports service status. Only a real chat request exercises downstream AI services.

06 / LIMITATIONS & TRADE-OFFS

Where the edges are.

  • Verification reduces risk; it does not establish zero hallucinations.
  • MemorySaver is process-local; server restarts can reset conversational memory.
  • Render may cold-start. API requests are rate-limited to 10 per minute per IP.
  • The experimental streaming route is not used by this portfolio.
